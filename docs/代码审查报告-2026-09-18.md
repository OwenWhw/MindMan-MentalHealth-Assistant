## 二、接口一致性审查

### 2.1 前端调用 → 后端不存在的接口（real 模式下必然 404）❌

| # | 前端调用 | 调用方 | 后端现状 | 修复建议 |
| --- | --- | --- | --- | --- |
| 1 | `POST /file/upload`（`api/file.js uploadFile`） | `ArticleFormDialog.vue`（文章封面上传）、`UserSettingsDialog.vue`（头像上传） | **无任何 FileController** | 二选一：① 后端补 `FileController`（本地磁盘存储 + 静态资源映射）；② 短期内前端这两处改用图片 URL 输入框。**当前文章封面/头像上传功能在 real 模式下是坏的** |
| 2 | `GET /chat/session/page`（`consult.js getSessionPage`） | 无页面使用（死代码） | 后端只有 `GET /chat/sessions`（非分页） | 删除前端该函数即可，无需补后端 |

### 2.2 后端存在 → 前端未调用的接口（非错误，标注待办）

| 端点 | 说明 |
| --- | --- |
| `GET /auth/me` | 前端登录态靠 localStorage 恢复，未校验 token 有效性——token 过期后需等首个 401 才发现 |
| `GET /chat/sessions/{id}` | 会话详情端点无人用，可保留备用或删除 |
| `GET /knowledge/category/page`、`GET /knowledge/category/{id}` | 分类分页/详情，前端只用 tree——可删或保留 |
| `POST /api/admin/prompt/*` 全部 6 个 | **昨天刚加的提示词模板管理后端已完成，前端还没有管理页面**——后台侧边栏无入口，属"缺少对应前端页面" |

### 2.3 文档漂移（三份文档均与实际不符）

`API_SPEC.md` 记录的 `POST /api/emotions`、`GET /api/emotions/today`、`POST /api/analysis/emotion`、`GET /api/articles?pageSize=` 等端点**在实际 Controller 中根本不存在**（实际是 `/api/emotion/garden`、`/api/analysis/overview`、`/api/knowledge/article/page` 等）——它是最早期设计稿。`接口文档.md` 与 `openapi.yaml` 同样停留在旧版。**建议**：以 13 个 Controller 的真实注解为准重新生成一份（可用 springdoc 自动导出，项目已集成 Knife4j），删除另外两份。

### 2.4 其它一致性风险

| 问题 | 位置 | 理由 |
| --- | --- | --- |
| 401 跳转写死 `window.location.href = '/login'` | `ai-vue/src/utils/request.js` L71/L96 | 项目是 **hash 路由**，正确地址应为 `/#/login`；当前写法会整页跳到 path 模式地址，命中 `pathMatch` 兜底后虽能回到 `/`，但多绕一圈且丢失回跳意图 |
| 后台路由守卫判断 admin | `router/index.js` L104-108 | 与后端 `JwtInterceptor` + `LoginUser.requireAdmin()` 双重校验一致，无问题 ✓ |
| mock 数据结构与 real 返回结构 | `api/mock.js` | 7 个模块双分支并存，字段演进时易只改一边——建议每次改接口字段时把 mock 同步列入 checklist |
