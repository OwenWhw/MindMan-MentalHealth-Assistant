# MindMan 测试手册（手把手版）

> 目标：跟着本手册逐阶段执行，每步都有「操作 → 预期结果 → 判读标准」。
> 会同时覆盖【接口测试】与【功能测试】，并逐条核对简历里写的项目能力点。
>
> 环境约定：
> - 后端：`http://localhost:8080`（本地跑 jar 或 IDEA 启动）
> - 前端：`http://localhost:5173`（`npm run dev`）
> - 账号：`admin / 123456`（管理员）
> - Windows 下 curl 访问本机**必须加 `--noproxy "*"`**，否则走代理返回 502

## P1 认证与权限

### P1-1 登录成功
```bash
curl -s --noproxy "*" -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}'
```
**预期**：`code:200`，`data.token` 有值、`data.role:"admin"`。✅
**判读要点**：token 是 JWT（三段点分结构），`expiresAt` 为 7 天后。

### P1-2 取 token 供后续使用（建议每步都先执行）
```bash
TOKEN=$(curl -s --noproxy "*" -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")
echo ${TOKEN:0:30}
```

### P1-3 密码错误
```bash
curl -s --noproxy "*" -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"wrong"}'
```
**预期**：被拒绝（`code:400`）。⚠️ 严格来说应返回 401，属待优化项。

### P1-4 无 token 访问受保护接口
```bash
curl -s --noproxy "*" -o /dev/null -w "%{http_code}\n" http://localhost:8080/api/auth/me
```
**预期**：`401`。✅

### P1-5 携带 token 获取用户信息
```bash
curl -s --noproxy "*" http://localhost:8080/api/auth/me -H "Authorization: Bearer $TOKEN"
```
**预期**：`data.username == "admin"`。✅

## P2 情绪管理模块

```bash
curl -s --noproxy "*" http://localhost:8080/api/emotion/garden -H "Authorization: Bearer $TOKEN"
```
**预期**：`code:200`，`data` 为花朵列表（每朵含情绪类型/颜色/日期）。✅

curl -s --noproxy "*" -X POST http://localhost:8080/api/emotion/garden \

**判读要点**：再次执行 P2-1，列表应多出一朵。

### P2-3 缺必填字段（`emotion`）

**预期**：参数校验失败，提示「请选择一种心情」。⚠️ 校验生效（HTTP 200 + 业务错误码为项目约定）。

### P2-4 情绪日记分页 + 本周洞察
```bash

```
**预期**：均 `code:200`；日记为分页结构（含 total/list），洞察含本周情绪统计。✅

## P4 AI 对话与流式（重点，简历核心能力点）

### P4-1 可用模型列表
```bash
curl -s --noproxy "*" http://localhost:8080/api/chat/models -H "Authorization: Bearer $TOKEN"
```
**预期**：返回模型列表（对应「多模型切换」）。✅

### P4-2 AI 通道诊断
```bash
curl -s --noproxy "*" http://localhost:8080/api/admin/prompt/channels -H "Authorization: Bearer $TOKEN"
```
**预期**：`cloud.available`、`ollama.enabled/available`、`current` 为当前生效通道（ollama 或 cloud）。✅
**判读要点**：这是「云端/本地双通道」能力的直接证据。

### P4-3 创建会话
```bash
SID=$(curl -s --noproxy "*" -X POST http://localhost:8080/api/chat/sessions \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{}' \
  | python -c "import sys,json;d=json.load(sys.stdin)['data'];print(d['id'] if isinstance(d,dict) else d)")
echo $SID
```
**预期**：返回新会话 id。✅

### P4-4 SSE 流式对话（逐字返回）
```bash
curl -s --noproxy "*" -N -X POST http://localhost:8080/api/chat/stream \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d "{\"sessionId\":$SID,\"content\":\"我最近总是失眠，白天很累，有什么建议吗？\"}" | head -20
```
**预期**：连续出现
```
event:message
data:{"text":"我","done":false}
```
等逐段输出（**不是一次性整段**），最后一条 `done:true`。✅
**判读要点**：这就是简历写的「服务端 SSE 流式逐字返回」。首包延迟：模型冷启动可达 5-8s，热身后 <300ms（实测 276ms）。

### P4-5 同步对话（非流式）
```bash
curl -s --noproxy "*" -m 300 -X POST http://localhost:8080/api/chat/messages \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d "{\"sessionId\":$SID,\"content\":\"谢谢，我会试试看。\"}"
```
**预期**：`code:200`，返回 AI 回复（耗时数秒）。✅

### P4-6 多轮上下文 & 历史消息
```bash
curl -s --noproxy "*" "http://localhost:8080/api/chat/sessions/$SID/messages" -H "Authorization: Bearer $TOKEN"
```
**预期**：能看到 user/assistant 交替的多轮消息（对应「多轮上下文对话」）。✅

### P4-7 会话不存在时的兜底
```bash
curl -s --noproxy "*" -X POST http://localhost:8080/api/chat/messages \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"sessionId":999999,"content":"你好"}'
```
**预期**：业务码 404（会话不存在），**不抛 500**。✅

## P5 提示词模板与 RAG

### P5-1 模板列表
```bash
curl -s --noproxy "*" http://localhost:8080/api/admin/prompt/list -H "Authorization: Bearer $TOKEN"
```
**预期**：≥3 条（chat_system / quote_gen / article_recommend）。✅

### P5-2 模板渲染（变量替换）
```bash
curl -s --noproxy "*" -X POST http://localhost:8080/api/admin/prompt/render \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"scene":"quote_gen","vars":{"count":"3"}}'
```
**预期**：`rendered` 中 `{count}` 被替换为 `3`，`source` 为 `db:...`。✅

### P5-3 新增模板 + 启用互斥
```bash
curl -s --noproxy "*" -X POST http://localhost:8080/api/admin/prompt/save \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"scene":"manual_test","name":"手工测试模板","template":"测试 {v}","enabled":1}'
```
**预期**：`code:200` 并返回带 id 的对象；再查列表能看到它。✅

### P5-4 模板即时生效（关键）
改 `chat_system` 模板内容（如加一句「回复结尾加 🌱」）→ 再跑一次 P4-5，回复应带上该特征。
**预期**：提示词改动**无需重启**即生效。✅

### P5-5 RAG 索引状态
```bash
curl -s --noproxy "*" http://localhost:8080/api/admin/rag/status -H "Authorization: Bearer $TOKEN"
```
**预期**：`enabled:true`、`embeddingModel:"nomic-embed-text"`、`indexedChunks` ≥ 100。✅

### P5-6 RAG 检索真实命中
提问一个与文章相关的问题（如「什么是正念？」），然后看后端日志：
```bash
grep "\[RAG\] 命中" <后端日志文件>
```
**预期**：出现 `[RAG] 命中 N 个片段: 文章标题(0.xx)`。✅
**判读要点**：这是「集成向量数据库实现知识库 RAG 检索增强」的直接证据。

### P5-7 重建索引
```bash
curl -s --noproxy "*" -m 600 -X POST http://localhost:8080/api/admin/rag/reindex -H "Authorization: Bearer $TOKEN"
```
**预期**：返回 `indexedChunks`（当前为 104）。✅
